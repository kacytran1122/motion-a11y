Accessibility linting for animation code

Your linter reads
your JSX. It never
reads your motion.

Animation is the one part of the front end that nothing checks. ESLint reads JSX attributes, so it cannot see a GSAP timeline. Stylelint reads CSS, so it cannot see repeat: Infinity inside a JavaScript object. Axe runs against a rendered page, so it cannot see an animation that has not started yet.

motion-a11y reads the JavaScript. That is where the animation actually lives.

The seven rules

  
Each one maps to a
real WCAG criterion.

  

    No style opinions and no taste calls. Every rule points at a published success criterion, so a
    finding is something you can take to a product manager rather than an argument about polish.
  


  


    

      
require-reduced-motion-guarderror

      
The file animates but never checks whether the reader asked for less motion. Reported once per file, not once per call, so it stays readable.

      
// no useReducedMotion anywhere in this file
<motion.div animate={{ x: 200 }} />

      
WCAG 2.3.3 Animation from Interactions

    


    

      
no-fast-flasherror

      
A repeating animation changes opacity or colour more than three times a second. This rule still fires in a file that has a reduced motion guard. See below for why.

      
el.animate([{ opacity: 0 }, { opacity: 1 }], {
  duration: 120, iterations: Infinity
});

      
WCAG 2.3.1 Three Flashes or Below Threshold

    


    

      
no-infinite-animationerror

      
Motion that repeats forever with no way to stop it. Passes if the file exposes a pause control, because that is what the criterion actually asks for.

      
gsap.to(".pulse", {
  scale: 1.1, repeat: -1
});

      
WCAG 2.2.2 Pause, Stop, Hide

    


    

      
no-scroll-linked-animationwarn

      
Motion tied to scroll position. About 35 percent of adults over 40 have some vestibular dysfunction, and scroll driven parallax is the strongest trigger on the web.

      
const { scrollYProgress } = useScroll();

      
WCAG 2.3.3 Animation from Interactions

    


    

      
no-long-animationwarn

      
An animation runs longer than five seconds with no pause control. Durations are read in the unit each library uses: seconds for GSAP and Motion, milliseconds for the Web Animations API.

      
gsap.to(".hero", { x: 400, duration: 12 });

      
WCAG 2.2.2 Pause, Stop, Hide

    


    

      
no-smooth-scrollwarn

      
A smooth scroll request with no fallback. Catches the options object and the property assignment, including when the call sits in the middle of a chain.

      
document.querySelector("#top")
  .scrollIntoView({ behavior: "smooth" });

      
WCAG 2.3.3 Animation from Interactions

    


    

      
no-autoplay-lottiewarn

      
A Lottie player starts on load. Covers the React components and lottie-web's loadAnimation, including a bare autoplay attribute.

      
<Lottie animationData={data} loop autoplay />

      
WCAG 2.2.2 Pause, Stop, Hide

    


    

      
Two presets

      
recommended is the default and mixes errors with warnings. strict makes every rule an error. Any single rule can be turned off or changed.

      
motion-a11y src --preset strict
motion-a11y src --rule no-smooth-scroll=off

      
Run motion-a11y --rules to print the table

    


  







  
One deliberate exception

  
The flash rule ignores your reduced motion guard.

  

    Every other rule goes quiet once the file respects the reader's motion preference. no-fast-flash
    does not, and that is on purpose.
  

  

    Most people who are photosensitive have never opened their operating system settings and switched
    reduced motion on. Many do not know the setting exists. A seizure risk is not a preference to
    respect, so the rule asks you to fix the flash rate itself rather than hide it behind a media
    query. If you disagree for a specific file, turn the rule off explicitly. That is a decision
    somebody made, which is the point.
  







  
Guard detection

  
What counts as checking
the motion preference


  

    

      

        A file is treated as guarded when any of these appear. Guards are read from the syntax tree
        rather than the raw text, so a mention inside a comment does not silence anything.
      

      

        Guards are checked per file, not per branch. A file with a guard in one function and an
        unguarded animation in another will pass. That is a deliberate trade. False positives are the
        fastest way to get a linter switched off, and a rule nobody runs catches nothing.

Three ways to run it

  
Same rules.
Pick your surface.


  

    

      One
      
On the command line

      
Point it at a folder. It skips node_modules and build output on its own. Exit code is 1 when there is an error, so it drops straight into a pre-commit hook.

      
npm i -D motion-a11y

npx motion-a11y src

    


    

      Two ★
      
In your pull requests

      
The github format prints annotations, so each finding lands inline on the diff next to the line that caused it. Reviewers see it without opening the log.

      
- run: npx motion-a11y src \
    --format github

    


    

      Three
      
From your own code

      
Full TypeScript types, ESM and CommonJS. Parse errors come back on the result instead of throwing, so one bad file cannot take down your build script.

      
import { lint } from "motion-a11y";

const r = lint(src, {
  filename: "Hero.tsx"
});

    

  







  
What it does not do

  
A linter is only worth
keeping if it is honest.


  

    

      
It does not read CSS

      
Keyframes and transitions in a stylesheet belong to stylelint-a11y and its media-prefers-reduced-motion rule. Run both. They do not overlap.

    

    

      
It does not judge taste

      
Only mechanical facts: rate, length, repetition, and whether a guard exists. Whether an animation feels comfortable is a human call.

    

    

      
Values must be literals

      
duration: SPEED cannot be resolved without running your code, so it is skipped rather than guessed at.

    

    

      
Guards are per file

      
Not per branch or per component. This keeps false positives low, at the cost of missing a mixed file.
